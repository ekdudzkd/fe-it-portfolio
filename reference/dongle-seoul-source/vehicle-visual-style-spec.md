# 차량 미술·형태 기준 (Vehicle Visual Style Spec)

2026-10-21 · 서울섬 자동차 콘텐츠 13단계 중 **2단계** 산출물 · 상태: 확정

이 문서는 게임에 나오는 모든 차량(기본 절차형 차, 꾸민 차, 사진·그림으로 만든 GLB, 다른 주민 차)의
겉모습·크기·재질·꾸미기 영역·GLB 규격의 **단일 기준**이다. 성능 수치·가격·등급은 3단계 이후에 정한다.

  `AGENTS.md` 는 저장소에 없다(2026-10-21 `origin/main` 7599a1a 기준). 그래서 새 문서 하나를 기준으로 삼는다.

## 1. 단위와 좌표 (먼저 읽기)

| 용어 | 뜻 |
|---|---|
| **로컬 m** | `Car.root` 안의 좌표. 모델링·GLB·템플릿 숫자는 전부 이것이다. 기본 차 몸통 `rbox(1.5, 0.5, 2.6)` 이 이 단위다 |
| **월드 u** | 섬 좌표. `Car.root.scale = ACTOR = 0.5` 이므로 **월드 = 로컬 × 0.5**. 지도 1칸 = 1.0 월드 u |
| 축 | three.js Y-up 오른손 좌표. 차 앞 **+Z**, 위 +Y, 운전자 기준 왼쪽 +X, 오른쪽 −X |
| 원점 | 차체 XZ 가운데, 바닥 Y=0 (바퀴가 땅에 닿는 높이) |

비교 기준: 캐릭터 키 1.70 로컬(0.85 월드), 기본 카메라 거리 7.0 월드(줌 3.5~28), 시야각 46°(세로 화면 62°), 기본 피치 0.55 rad.

## 2. 미술 방향

### 2.1 한 줄 정의

**"손바닥 위의 단단한 미니카"** — 실제 차를 길이 60%·높이 85% 정도로 줄인 땅딸막한 비율, 둥근 상자 조각,
3단 툰 명암, 서울섬 파스텔 색. 귀엽지만 장난감 플라스틱처럼 가볍게 보이지 않도록 **바퀴·하부는 어둡고 묵직하게**,
**차체 아래 띠(보조색)로 무게중심을 낮게** 잡는다.

### 2.2 단순화·과장 규칙

| 항목 | 규칙 |
|---|---|
| 비율 | 실차 길이:높이 ≈ 3:1 을 **2:1 ~ 2.7:1** 로 압축. 실차 폭:높이 ≈ 1.25 를 1.25~1.7 로 넓힘 |
| 바퀴 | 실차보다 크게: 바퀴 반지름 = 전고의 **0.20~0.28**(SPORTS 만 0.28). 바퀴는 차체 옆면에서 0~0.06 m 바깥으로 나와 보인다 |
| 조각 | 모든 차체 조각은 `rbox` 같은 **둥근 상자**(모서리 반경 = 가장 짧은 변 × 0.3, 최대 0.16 m) 또는 그에 준하는 낮은 각 수 곡면 |
| 생략 | 문틈선, 와이퍼, 안테나, 사이드미러, 그릴 세부, 배기구, 번호판, 엠블럼, 실내(오픈카 좌석 제외) |
| 남김 | 차종 실루엣, 지붕선, 창 띠, 전조등·후미등 위치, 바퀴 크기, 차체 아래 띠, 두 가지 색 구분 |
| 과장 | 전조등 크기(실차 대비 1.5배), 바퀴 크기, 차종별 높이 차이(§4 표의 지붕 높이 차를 줄이지 말 것) |

### 2.3 색감과 명암

- 명암은 `toonMat` 의 3단 그라데이션(100/180/255)만 쓴다. 부드러운 그라데이션·환경 반사·광택 하이라이트 없음.
- 색은 `soft()` 파스텔 보정을 거친 값으로 보인다(채도 ×1.1 상한, 밝은 유채색은 명도 0.88 상한, 아주 어두운 색은 따뜻한 갈색 기운).
- 그림자는 `blobShadow` 동그란 그림자 하나(기본 차 0.95×1.55 로컬). 그림자 맵에 의존하지 않는다.
- 건물·도로와 어울리는 근거: 도로 `#b9b5ab`, 광장 `#fff6e6`, 풀 `#6cc63f` 위에서 차체는 **명도 0.25~0.88**, 채도 ≤ 0.82 범위가 가장 잘 떠 보인다.

### 2.4 좋은 예

1. 기본 오픈카(`car.js makeBody`): 둥근 몸통 + 흰 아래 띠 + 크고 밝은 전조등 + 어두운 바퀴·밝은 허브.
2. 분홍 차체 + 흰 띠, 파랑 차체 + 밝은 회색 띠처럼 **차체색과 띠색 명도 차가 0.25 이상**인 조합.
3. SUV 가 경차보다 확실히 높고 바퀴가 크며, 스포츠카는 한눈에 납작하다(높이 차 ≥ 0.18 m).
4. 옆면에 별·번개 스티커 1~3개, 바퀴·창·등을 피한 자리.

### 2.5 금지 예

1. 반실사 PBR: 크롬 휠, 거울 같은 반사, 금속 플레이크, 유리 투명 굴절(예: 현재 `compact_hatchback.glb` 66k 삼각형).
2. 실차 비율 그대로(길이:높이 3:1 이상) 축소해 캐릭터 옆에서 길고 납작해 보이는 차.
3. 길이:높이 1.6:1 미만의 공·찐빵 모양, 바퀴 반지름이 전고의 0.30 이상인 몬스터 트럭 — 장난감처럼 가볍다.
4. 형광·네온 원색(채도 > 0.82), 순검정 차체에 보조색도 검정(밤에 사라짐).
5. 차 앞뒤가 구분되지 않는 대칭 상자(전조등·후미등 없음).
6. 상표·엠블럼·번호판·실제 차명 글자.
7. 한 장 판을 겹쳐 세운 종이 인형 같은 차 — `drawnCarBody` 는 임시 자리 모델이며 새 차종의 기준이 아니다.

## 3. 공통 차량 규격

### 3.1 숫자의 근거 (현재 코드에서 나온 상한)

| 제약 | 현재 값 | 차에 주는 한도 |
|---|---|---|
| 동네 도로(`RC.LOCAL`) 폭 | 반폭 0.5칸 → 최소 **1.0 월드** | `fits()` 는 차 모서리 점마다 반경 0.12 월드 여유를 본다 → 충돌 폭 ≤ 2×(0.5−0.12) = **0.76 월드 = 1.52 로컬** |
| 간선도로 폭 | 반폭 0.95칸 → 약 2.0 월드 | 두 대가 엇갈릴 수 있음 |
| 지천 작은 다리 | 1~2칸, 다리 근처 1.5 월드 안은 가운데 줄만 검사 | 충돌 길이 ≤ 2.6 로컬(1.3 월드)이면 현재 판정 그대로 통과 |
| 철도 입체교차 아래 | `PORTAL_H 1.4 − DECK 0.36 − CLEARANCE 0.35` | 전고 ≤ **0.69 월드 = 1.38 로컬** |
| 차고 | 실제 차고 건물·문 형상은 없다. 차고 = 보관 대수(`housing`) + `GaragePanel/VehiclePreview` 미리보기 | 미리보기 카메라는 `max(L, W, H)` 로 거리를 정하므로 **길이 2.70 로컬 이하**면 지금 구도 그대로 잘리지 않음 |
| 서버 GLB 경계 | V7 `bounds` 길이 2.0~6.5, 폭 1.0~2.8, 높이 0.6~2.8 m | 원본 GLB 허용 범위. 게임 안에서는 아래 외형 상자로 축소한다 |

### 3.2 확정 규격 (모든 차종 공통)

| 항목 | 로컬 m | 월드 u | 기본 차 대비 |
|---|---|---|---|
| 외형 최대 길이 L (등·범퍼 포함) | **2.70** | 1.35 | 1.007 |
| 외형 최대 폭 W (바퀴 바깥면 포함) | **1.72** | 0.86 | 1.012 |
| 외형 최대 높이 H (지붕·루프랙 포함) | **1.36** | 0.68 | 1.058 |
| 외형 최소 L / W / H | 2.20 / 1.50 / 1.00 | 1.10 / 0.75 / 0.50 | 0.82 / 0.88 / 0.78 |
| 충돌 폭 (`size.width`) | **1.50 고정** | 0.75 | 1.00 |
| 충돌 길이 (`size.length`) | **차종표 값 (2.22~2.60)**, 최대 2.60 | ≤ 1.30 | ≤ 1.00 |
| 차체 바닥(최저 지상고) | 0.16~0.32 (차종표) | 0.08~0.16 | 기본 0.25 |
| 원점 | XZ 중심 ±0.05, 바닥 Y=0 ±0.02 | | 서버 `originToleranceM`·`floorToleranceM` 와 같음 |
| 운전석 `seat` | 기본 `[0, 0.32, -0.2]`, 차종표 값 | | 지붕 차는 불투명 창이 앉은 캐릭터를 가린다. 캐릭터가 지붕 밖으로 보이는 것은 허용(실내를 만들지 않음) |

기본 차 실측(`DEFAULT_LOOK`): **L 2.68 × W 1.70 × H 1.285 로컬** = 1.34 × 0.85 × 0.643 월드. 몸통 상자 바닥 0.25.

### 3.3 바퀴 공통

| 항목 | 값 (로컬 m) |
|---|---|
| 개수·배치 | 4개, 좌우 대칭, 앞 2개(z>0)만 조향 |
| 반지름 r | 차종표 0.26~0.32. 전고의 0.20~0.28 |
| 타이어 폭 | **0.24 고정** (`makeWheel`) |
| 허브 | 반지름 0.45 r, 폭 0.26, 색 `#e6e6e6` |
| 좌우 간격(track) | 바퀴 중심 x = ±(W/2 − 0.12) ±0.01 → 허브 바깥면 = 외형 폭 |
| 앞뒤 간격(wheelbase) | 충돌 길이 × 0.62~0.68 (차종표) |
| 바퀴 중심 높이 | y = r (바닥에 닿음) |
| 앞뒤 돌출(overhang) | 앞 바퀴 중심 ~ 차 앞 끝 ≥ r + 0.12, 뒤도 같음 |

바퀴는 **템플릿 바퀴**(`DEFAULT_TEMPLATE.attachment.wheels` 꼴의 `[[x, z]...]` + `wheelRadius`)로 그린다. 그래야 `Car.sync` 가 굴리고 꺾는다.
GLB 안 바퀴는 지금 돌지 않으므로 새 차종 GLB 에 넣지 않는다(§8.4).

### 3.4 앞뒤 방향 기준

- 앞 = +Z. 앞에는 **밝은 노랑 전조등 2개**, 뒤에는 **빨강 후미등 2개**가 반드시 있다(전조등 lens 최소 0.24×0.12, 후미등 0.22×0.10 로컬).
- 옆에서 볼 때 앞뒤를 구분하는 단서가 하나 이상: 보닛이 트렁크보다 길다(경차·SUV 제외) 또는 앞 유리가 뒤 유리보다 기울었다.
- 옆면 꾸미기 템플릿은 차 앞이 **이미지 오른쪽**(`seoul-car.v1.json orientation.imageFront = right`).

### 3.5 충돌체와 외형 차이 허용

| 방향 | 외형 − 충돌 허용 범위 (로컬) |
|---|---|
| 폭 | 0 ~ +0.22 (바퀴·띠가 충돌 상자 밖으로 나오는 정도. 기본 차 +0.20) |
| 길이 | −0.10 ~ +0.12 (등·범퍼 돌출. 기본 차 +0.08) |
| 높이 | 충돌은 2D 라 높이 차이 규칙 없음. §3.2 최대 높이만 지킨다 |

차가 벽에 닿았을 때 외형이 벽을 0.06 월드 넘게 파고들면 안 된다. 위 범위는 `fits()` 여유 0.12 월드 안에 들어간다.

### 3.6 카메라에서 잘리지 않는 크기

- 섬 카메라: 기본 거리 7.0 월드에서 외형 최대(1.35 × 0.68 월드)는 화면 세로의 약 12% → 잘림 없음. 줌 최소 3.5 월드에서도 시야 안.
- 미리보기(`VehiclePreview`): `reach = max(L, W, H)` 로 카메라를 둔다. L ≤ 2.70 이면 지금 구도 유지.
- 반대로 너무 작아 보이지 않게 외형 최소(§3.2)를 둔다. 경차 2.30 길이는 기본 거리에서 화면 세로 약 10%.

### 4.3 앞·옆·위 비율표

비율은 외형 기준. 옆 = L:H, 앞 = W:H, 위 = L:W, 창 높이 = (지붕 − 벨트라인) / H.

| 차종 | 옆 L:H | 앞 W:H | 위 L:W | 창 높이 비 | 바퀴 r / H | 지상고 / H |
|---|---|---|---|---|---|---|
| OPEN | 2.08 | 1.32 | 1.58 | 0.25 (앞유리만) | 0.22 | 0.19 |
| KEI | 1.74 | 1.18 | 1.47 | 0.38 | 0.20 | 0.17 |
| SEDAN | 2.29 | 1.41 | 1.63 | 0.34 | 0.24 | 0.19 |
| SUV | 1.96 | 1.26 | 1.55 | 0.32 | 0.24 | 0.24 |
| SPORTS | 2.70 | 1.72 | 1.57 | 0.34 | 0.28 | 0.16 |

허용 오차: 위 비율은 ±5%, 지붕 높이 ±0.03 m, 바퀴 반지름 ±0.01 m. 이 범위를 넘으면 다른 차종으로 본다.

### 4.4 차종별 실루엣

| 차종 | 옆모습 한 줄 | 멀리서 구분하는 핵심 (기본 카메라 7 월드) |
|---|---|---|
| OPEN | 지붕 없는 둥근 욕조 + 기울어진 앞유리 + 좌석 등받이 | 지붕이 없다, 좌석이 보인다 |
| KEI | 앞이 거의 수직인 키 큰 상자, 보닛이 아주 짧다 | 가장 짧고 높이:길이가 가장 크다, 두 가지 색 지붕 |
| SEDAN | 보닛·실내·트렁크 3단, 지붕이 가운데 낮은 아치 | 가장 길고 트렁크 단이 있다 |
| SUV | 앞뒤가 거의 수직인 높은 2박스, 바퀴 둘레 어두운 휠아치 띠 | 가장 높고 바퀴가 가장 크다, 루프랙 |
| SPORTS | 긴 보닛, 뒤로 물린 낮은 실내, 쐐기 모양 | 가장 낮고 넓다, 뒤쪽 작은 스포일러 |

### 4.5 같은 차종끼리 통일할 것 / 바꿀 수 있는 것

- **통일(변경 금지)**: §4.2 치수, 실루엣 조각 구성, 바퀴 크기·위치, 등 위치, 창 띠 높이, 보호 재질 색(§5.2).
- **개성(차마다 다르게 가능)**: 차체색·보조색(§5.3), 옆면 스티커(§6), 허브 모양 3종(원판·5살·별) 중 하나, 등 모양 3종(원·각진 사각·가로 띠) 중 하나, 스포일러·루프랙의 유무(차종이 허용한 경우: SPORTS 스포일러 기본 있음/없음, SUV 루프랙 있음/없음, KEI 두 가지 색 지붕 켬/끔).
  모양 변형은 위 목록뿐이다. 길이·높이를 차마다 바꾸지 않는다.

## 5. 재질과 색상

### 5.1 재질 규칙

| 부위 | 재질 | 값 |
|---|---|---|
| 차체(주색) | 절차형 꾸민 차: `paintMaterial(hex)` (soft 없음, 옆면 decal 과 이음매 일치) / 그 밖: `toonMat` | 3단 툰 |
| 보조색 띠 | 위와 같음 | |
| 유리 | 오픈카 앞유리: `basic({ color: '#cfeaf6', transparent, opacity: 0.75 })`. 지붕 차 창: **불투명** `toonMat('#cfeaf6')` (실내를 만들지 않음) | |
| 타이어 | `toonMat('#2b2b33')` | |
| 허브 | `toonMat('#e6e6e6')` | |
| 휠아치·범퍼·트림 | `toonMat('#34343c')` | 템플릿 `archTrims` 색과 같음 |
| 전조등 | `basic({ color: '#fff6c8' })` (빛을 받지 않음 → 밤에도 밝음) | |
| 후미등 | `basic({ color: '#ff6b6b' })` | |
| 좌석(OPEN) | `toonMat('#fff3d6')` | |

- 재질은 반드시 `toonMat` / `basic` / `paintMaterial` 중에서 고른다(캐릭터용 `charMat` 금지). 셋 다 `stylize` 를 거쳐 휘는 지평선·색 보정·가로등 빛을 받는다.
  그냥 `MeshStandardMaterial` 을 쓰면 줌아웃 때 차체가 떠 보인다(`toonify` 주석의 버그).
- 금지: `metalness`, `roughness`, `envMap`, `specular`, `shininess`, 법선맵, 광택맵, 환경맵. `toonMat` 이 지워 버리므로 GLB 에 넣어도 의미 없다.
  서버 스타일 프로필(`asset_style_profiles seoul-island v1`)도 metallic 0 · roughness 0.85.
- 텍스처는 차체에 쓰지 않는다. 예외는 꾸미기 옆면 decal texture(1024×512) 와 GLB 정점색(COLOR_0) 뿐.

| 1 | `#FF8FA3` | `#FFFFFF` | | 5 | `#FFB020` | `#3A3220` |
| 2 | `#C61E32` | `#111111` | | 6 | `#7A4FD0` | `#FFD23F` |
| 3 | `#2E6BD8` | `#F5F5F5` | | 7 | `#F5F5F5` | `#2B2B33` |
| 4 | `#3FA34D` | `#FFE14D` | | 8 | `#111111` | `#E8461E` |

다른 주민 차 기본색 `#8FC7FF`. 사진·그림 변환 결과를 붙잡는 섬 팔레트는 worker `PALETTE_HEX`
(`#2b2b33 #ff6b6b #ff8fa3 #ffb703 #6ad28a #5aa9e6 #9b7ede #8b5e3c #ffffff #cfeaf6 #fff3d6`), 붙잡기 ΔE 30, 못 붙잡으면 채도 ≤ 0.82 · 명도 0.18~0.94 로 자른다.

### 5.3 사용자가 바꿀 수 있는 영역 / 안전 영역

| 영역 | meshTag | 사용자 색 변경 |
|---|---|---|
| 차체 껍데기(몸통·보닛·트렁크·문·지붕) | `body` | **가능** (주색) |
| 차체 아래 띠, KEI 두 가지 색 지붕 | `secondary` | **가능** (보조색) |
| 옆면 decal 면 | `decal-surface-left/right` | 스티커만 (§6) |
| 유리 | `protected-glass` | 불가 |
| 타이어·허브·휠아치·범퍼·트림 | `protected-wheel` (트림 포함) | 불가 |
| 전조등·후미등 | `protected-light` | 불가 |
| 좌석 | `interior` | 불가 |

새 차종의 모든 mesh 는 위 태그 중 하나를 `userData.meshTag` 로 가져야 한다. 태그 없는 mesh 는 안전 영역으로 취급한다.

### 5.4 밤에도 보이게

- 전조등·후미등은 `basic` 재질이라 밤에 꺼지지 않는다. lens 최소 크기(§3.4)를 지킨다.
- 차체색이 명도 0.25 미만이면 보조색은 명도 0.55 이상이어야 한다(프리셋 2·8 은 띠색이 아니라 등으로 읽히므로 허용, 새 프리셋은 이 규칙을 지킨다).
- 앞뒤 방향은 등 색(앞 노랑·뒤 빨강)으로 읽힌다. 차체 모양만으로 방향을 알리려 하지 않는다.

## 6. 꾸미기 호환 기준

### 6.1 구조 재사용

- 기존 구조(`Customization v1` JSON · `VehicleTemplate` manifest · `compositor.js` · `vehicle/vehicleAppearance.js` 의 raycast decal surface)를 **그대로 재사용**한다.
- 차종마다 템플릿 manifest 하나: `seoul-car` v1(OPEN, 기존 그대로) · 신규 `seoul-kei`, `seoul-sedan`, `seoul-suv`, `seoul-sports` 각 v1.
- 신규 manifest 는 `seoul-car.v1.json` 과 같은 `logicalSize 1024×512`, `orientation`, `supportedSides [left, right]`, 마스크 3종, `surface3d` 구조를 쓴다. 다른 점은 `projection` 뿐:
  `zFromU = { origin: −L/2, span: L }`, `yFromV = { origin: L/2, span: −L/2 }` (L = 차종 외형 길이). 그래서 `metersPerPixel = L/1024`.

### 6.2 스티커를 붙일 수 있는 영역 (차 옆면만)

차종별 옆면 decal 가능 영역(로컬 m). 이 사각형에서 바퀴 구멍과 등 영역을 뺀다.

| 차종 | z 범위 | y 범위 |
|---|---|---|
| OPEN (기존 bodyPanel) | −1.24 ~ +1.24 | 0.30 ~ 0.72 |
| KEI | −1.09 ~ +1.09 | 0.32 ~ 0.78 |
| SEDAN | −1.29 ~ +1.29 | 0.32 ~ 0.74 |
| SUV | −1.27 ~ +1.27 | 0.42 ~ 0.88 |
| SPORTS | −1.29 ~ +1.29 | 0.26 ~ 0.62 |

공통 규칙: 위 끝 = 벨트라인 − 0.04, 아래 끝 = 아래 띠 위(지상고 + 0.10), 앞뒤 끝 = 차 끝에서 0.06 안쪽.
바퀴 구멍 = 바퀴 중심, 반지름 r + 0.04 원(기본 차 0.32 m = 126 px). 등 = 옆에서 보이는 등 사각형 + 0.02 여유.
지붕·보닛·앞뒤 면·유리에는 스티커를 붙이지 않는다.

### 6.3 좌우·앞뒤 기준

- 두 면 모두 이미지 오른쪽이 차 앞(+Z), u 는 뒤→앞, v 는 위→아래. 오른쪽 면을 몰래 좌우 반전하지 않는다. 반전은 `decal.flipX` 로만.
- left 면 = +X 쪽(운전자 왼쪽), 법선 [1, 0, 0]. right 면 = −X, 법선 [−1, 0, 0].

### 6.4 보호 규칙

- 유리·바퀴·등·좌석에는 색도 스티커도 들어가지 않는다(protected mask 로 잘라 냄).
- 문은 따로 나누지 않는다. 문은 `body` 의 일부이고 문틈선을 그리지 않으므로 스티커가 문을 가로질러도 된다.

### 6.5 꾸민 뒤에도 차종이 읽히는 제한

- 스티커는 면당 최대 8개(기존 스키마 한도 유지), 한 면 decal 덮인 면적은 decal 영역의 **60% 이하**를 권장(편집기 경고 기준). 100% 를 막지는 않는다.
- 스티커로 차 모양을 바꾸는 효과(가짜 바퀴·가짜 창·가짜 등)를 막기 위해 stock decal 은 추상 무늬만 둔다.
- 차체색으로 유리·바퀴·등 색을 흉내 내도 보호 재질 색이 따로 남으므로 실루엣은 유지된다.

### 6.6 GLB 차의 칠하기

- GLB 는 `vertex-weight-v1`(`_SI_PAINT_0` 정점 가중치) 계약을 선언했을 때만 주색을 바꿀 수 있다. 가중치 1 = `body`, 0 = 그 밖.
- GLB 에는 옆면 decal 을 붙이지 않는다(UV·마스크 계약 없음). GLB 차의 꾸미기는 주색 하나뿐이다.

## 7. 실제 사진 → 게임 차량 변환 기준

### 7.1 원칙: 모양은 차종 템플릿, 사진은 색과 무늬만

사진에서 3D 형상을 복원하지 않는다. 결과는 **§4 의 차종 하나 + Customization v1 JSON**(주색·보조색·옆면 스티커)이다.
이것이 원본과 닮았지만 복제 모델이 되지 않게 하는 핵심 장치다.

### 7.2 반드시 유지할 특징

1. 차종: 사진 차의 옆모습 비율로 KEI / SEDAN / SUV / SPORTS / OPEN 중 가장 가까운 것 (지붕 없음 → OPEN, 길이:높이 < 2.4 → KEI, 지붕 높이 / 전고 ≥ 0.6 이고 지상고 큼 → SUV, 길이:높이 > 3.2 → SPORTS, 나머지 → SEDAN). 판정 신뢰도가 낮으면 SEDAN 으로 두고 사용자가 고른다.
2. 차체 대표색 (섬 팔레트로 붙잡거나 자른 값)
3. 두 번째 색이 있으면 보조색 (차체색과 ΔE ≥ 20)
4. 크게 보이는 줄무늬 1개 (기존 worker stripe 규칙: 높이 4~25%, 길이 60% 이상)
5. 지붕색이 다르면 KEI 두 가지 색 지붕 켬(그 밖 차종은 보조색으로만 반영)

### 7.3 게임 스타일로 단순화할 특징

그릴·헤드램프 세부 모양, 휠 디자인(허브 3종 중 밝기가 가까운 것), 반사·하이라이트, 먼지·흠집, 작은 장식 선,
창 틴팅 농도(항상 `#cfeaf6`), 실내, 미러·와이퍼·안테나.

### 7.4 브랜드·번호판·상표

- 로고·엠블럼·차명 글자·번호판은 **항상 제거**하고 다시 그리지 않는다. 그 자리는 주색으로 채운다.
- 사진 속 글자·로고는 스티커 후보에서 뺀다. 특정 브랜드를 알리는 고유 그릴 모양·고유 줄무늬 이름 배치도 재현하지 않는다.
- 결과물 이름에 실제 차명을 자동으로 넣지 않는다.

### 7.5 배경·사람·그림자

- 전경 분리는 기존 `segment.py` 기준을 따른다: 차 면적 ≥ 6%, 가로 폭 ≥ 35%, 두 번째 전경이 첫 번째의 35% 이상이면 "여러 대" 실패.
- 사람·배경·다른 차·바닥 그림자의 색은 대표색 계산에서 뺀다. 차 아래 어두운 띠(그림자)는 명도 30 미만 + 차 하단 15% 영역이면 그림자로 본다.
- 바닥 그림자는 결과에 넣지 않는다. 게임 그림자는 `blobShadow` 하나.

### 7.6 한 장으로 확인할 수 없는 부분

- 보이지 않는 반대쪽 옆면: 보이는 면의 스티커를 `flipX` 로 같은 앞뒤 방향에 복제한다.
- 지붕·보닛·뒷면: 주색. 앞에서만 찍어 옆 무늬를 모르면 스티커 없이 색만.
- 추측한 값은 결과 JSON 의 해당 항목 `confidence` 를 낮게 남기고 편집기에서 확인하게 한다.

### 7.7 복제 방지 기준

- 형상은 항상 §4 템플릿. 사진 텍스처를 차체에 투영하지 않는다.
- 사진에서 잘라 만든 스티커는 면당 1개, decal 영역의 40% 이하, 섬 팔레트 6색 이하로 줄인 그림만.

### 7.8 합격 / 실패 판정

**합격** (모두 만족)
1. 차종이 §4.1 목록 중 하나로 정해짐
2. 결과 주색이 사진 차체 대표색과 ΔE ≤ 15 (팔레트로 붙잡은 경우 붙잡은 팔레트색이 대표색과 ΔE ≤ 30)
3. 보호 영역(유리·바퀴·등)에 색·스티커가 없음
4. 글자·로고·번호판 픽셀이 결과 스티커에 없음
5. Customization v1 스키마 검증 통과

**실패** (하나라도 해당하면 결과를 저장하지 않고 다른 사진을 요청)
- 흐림(edge energy < 5.0), 너무 어두움, 차 면적 < 6%, 차 폭 < 35%, 여러 대
- 차가 아님(전경이 차 비율이 아님), 지원하지 않는 형식
- 대표색 표본 < 200 픽셀
- 결과가 기본값(기본 프리셋 색 그대로, 스티커 0)과 같음 — 분석이 아무것도 못 찾은 것

## 8. 기술 규격

### 8.1 모델 만드는 순서 (구현자 체크리스트)

1. 차종을 §4.1 에서 고른다.
2. §4.2 치수대로 `rbox` 조각으로 몸통·실내·보닛·트렁크를 만든다(절차형 우선). 원점·축은 §1.
3. 모든 mesh 에 §5.3 meshTag, 주색 mesh 에 `userData.seoulislandPaintSlot = 'primary'`.
4. 재질은 §5.1 표 그대로.
5. 바퀴는 템플릿 바퀴(`attachment.wheels`, `wheelRadius`)로. 차체에 넣지 않는다.
6. §6.1 의 manifest 와 마스크 3종을 `shared/vehicle-customization/tools/build-template-assets.mjs` 방식으로 만든다.
7. `new THREE.Box3().setFromObject(차체+바퀴)` 가 §4.2 외형과 ±0.02 이내인지 테스트로 고정한다(`tests/roadPlan.test.js` 의 높이 검사처럼).

### 8.2 GLB 좌표·단위

| 항목 | 값 |
|---|---|
| 형식 | glTF 2.0 binary (.glb), 외부 파일 참조 없음 |
| 단위 | 미터 (로컬 m). 실차 크기로 와도 되지만 게임에서 §8.6 규칙으로 줄인다 |
| 축 | +Y 위, +Z 앞 |
| 원점 | XZ 가운데(±0.05), 바닥 y=0(±0.02) |
| 노드 스케일 | 모든 노드 scale 1, 회전 없음 권장 |
| 장면 extras | `seoulislandVehicle: { wheels: 'template', appearance?: { primaryPaint: { kind: 'vertex-weight-v1', attribute: '_SI_PAINT_0' } } }` |
| AI 차체 바퀴 자리 | `seoulislandVehicle.wheelMask: { ok, attribute: '_SI_WHEEL_0', runs, axles: [{ z, y, r }], trackHalf }` + 정점 속성 `_SI_WHEEL_0` (1 = 생성 바퀴). 바퀴 선택(자동 · 생성된 바퀴 유지 · 기본 바퀴)에 씀. 확실하지 않으면 `ok: false` |

### 8.3 예산

### 8.4 바퀴 분리와 이름

- 새 차종 GLB 는 바퀴를 넣지 않고 `wheels: 'template'` 을 선언한다. 런타임이 템플릿 바퀴만 굴리고 꺾기 때문이다.
- 예전 생성 GLB(`wheels` 표시 없음 또는 `'embedded'`)는 지금처럼 그대로 보인다(바퀴 안 돎).
- 나중에 GLB 바퀴를 돌리게 될 때를 위해 이름을 예약한다: `Wheel_FL/FR/RL/RR`(회전축 노드, 원점 = 바퀴 중심), 앞바퀴 위에 `Steer_FL/FR`. 등은 `Light_Headlight_L/R`, `Light_Tail_L/R`.

### 8.5 같은 GLB 를 여러 차가 쓸 때

- 지금 방식 유지: 캐시 원본(`loadVehicleGlb`, 최대 4개)은 손대지 않고, `instantiateVehicleModel` 이 **칠할 재질만 차마다 복제**한다. geometry 는 공유.
- 색 바꾸기는 uniform 값만 바꾼다(다시 컴파일·다시 다운로드 없음). 프로그램 캐시 키는 칠하는 방식마다 하나.
- 정리할 때 `disposeVehicleAppearance` 로 그 차가 가진 재질만 버린다. 공유 geometry·원본 재질·`toonMat` 캐시 재질을 dispose 하지 않는다.
- 금지: 원본 재질의 `color` 를 직접 바꾸기, 차마다 `toonMat({...})` 새로 만들기(캐시 우회), 원본 geometry 의 정점색 수정(`softenVertexColors` 는 로드 때 한 번만).

### 8.6 잘못된 GLB 처리

| 상황 | 처리 |
|---|---|
| 서버 경계·예산 초과, 축·원점 어긋남, 깨진 파일, 삼각형 아닌 primitive | 서버/worker 가 **거부**(`OUTPUT_TOO_LARGE`, `OUTPUT_GLB_CORRUPT` 등). 저장하지 않음 |
| 경계 안이지만 게임 외형보다 큼 | `fitBody` 로 **한 배율로 축소**해 그 차종의 외형 상자(§4.2, 차종을 모르면 OPEN 상자 = `DEFAULT_LOOK`) 안에 넣음. 비율은 바꾸지 않음 |
| 축소 결과가 외형 상자 길이·높이의 70% 미만 (비율이 차종과 너무 다름) | 기본 차로 대체하고 `reason: 'shape-out-of-class'` 를 남김 *(구현 필요)* |
| 법선 없음 | `toonify` 가 `computeVertexNormals` |
| 금속·PBR 재질 | `toonify` 가 `toonMat` 으로 바꿈 |
| 불러오기 실패·네트워크 오류 | 지금처럼 기본 차(`makeBody(DEFAULT_BODY_COLOR)`)로 계속 탄다 |
| 칠하기 마스크가 하나라도 깨짐 | 칠하기 전체 `unsupported` (원본 색) |

## 10. 남은 위험

1. `assets/vehicles/compact_hatchback.glb` 는 66k 삼각형·반실사로 이 기준의 금지 예다. 게임에 연결하려면 다시 만들어야 한다.
2. 차종마다 꾸미기 템플릿 manifest·마스크를 새로 만들어야 한다(4종). 만들기 전까지 신규 차종은 주색만 바꿀 수 있다.
3. `fitBody` 가 차종을 모르면 SUV GLB 가 OPEN 높이(1.285)에 맞춰 작아진다.
4. 충돌 상자가 2D 라 차종 높이 차이가 다리·고가 아래 판정에 쓰이지 않는다. 최대 높이 1.36 을 넘는 차종을 추가하면 철도 높이 상수를 다시 봐야 한다.
5. 사진 차종 판정(§7.2-1)은 아직 worker 에 없다. 그 전까지는 사용자가 차종을 고른다.

## 11. 3단계에서 정할 것

- §4.1 차종 5개(`OPEN`, `KEI`, `SEDAN`, `SUV`, `SPORTS`)의 성능(`physics`: maxSpeed·boostSpeed·accel·brake·reverse·steer·offroad·coast)
- 차종 간 성능 차이의 폭과 상한(기본 `OPEN` 대비 비율)
- 차종별 획득 방법과 등급·가격(3단계 이후)
- 충돌 크기는 이 문서 §4.2 값으로 고정이며 3단계에서 바꾸지 않는다.
